# CFS真实接线与Go/R4-noformat三臂对比

结论：候选接线及聚焦回归完成，独立审查允许性能观察。yield明显改善，短任务存在退化，是否接受由用户决定；候选保留，未自动撤销、未提交、未推送或合入。

## 实现及身份

- 候选分支 `perf/411-cfs-local-integration`，源码内容身份 `6a9c66d3cf7af4a541974b9b6a321e226ad42531deefd28974153f484d767bdb`。
- 基线 R4-noformat `7d9c295890105a978b6aee4e4109db7967acc8af218474747f21a1873f353c5f`；同一冻结driver `1cbebe958656867652f11a22f8b5f2bf08cc8e70b9a1e233e921c64f515443e3`。Go1.27.3；GCC15.2 Release，同构编译配方。
- Coroutine持有累计服务、虚拟服务及相对迁移债务。每P单一mutex保护的侵入式CFS排序集合及floor；Take导出相对债务，目标按本地floor重定位，global不清账。Account在CommitPark发布前完成并清空队列running引用；READY回本P。
- 旧priority预算字段数值50/150/200/600改作相对权重，业务显式优先级、READY NORMAL、事件LOW降级与超时/取消CRITICAL提升保留。这是可观察的配置语义变化；公开交付文档仍需同步。
- 最多64次Resume形成一调度轮次，保持driver before/after、每4轮global检查、全局激活广播/持久latch/睡前复查、steal及退役门禁。

## 公平性及含义

- yield16个actor全部进展。三轮中最大/最小完成数比值的最坏值：单P CFS1.0092、基线1.000006、Go1.0444；双P CFS1.0578、基线1.0059、Go1.0047。不是服务时间或长期饥饿证明；CFS跨P不承诺全局精确公平。短任务仅一个提交actor，其计数比值没有协程公平性判别力。
- yield双P的CFS吞吐在此负载超过Go，但Go Gosched和本候选local READY的共享/迁移策略不同，不代表通用运行时全面领先。
- 当前变化同时包含CFS排序、READY本地回队、全局refill/轮次策略及同步结构调整。减少global往返是机制事实，尚未测量各项成本份额，不能把全部收益归因于CFS算法。
- 短任务双P三轮吞吐分别下降25.85%/14.85%/7.68%，P99增加44.92%/14.16%/2.19%；波动与一致退化方向都必须保留。未追加试验解释来源，不能只说噪声。
