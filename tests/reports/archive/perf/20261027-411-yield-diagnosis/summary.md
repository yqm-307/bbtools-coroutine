# R4／Go yield 短路径最小判别实验

结论：关闭日志时仍执行的两次格式化，是本轮实际测到的可削减成本；仅缩短单项 global refill 交接，在双 worker 上未建立稳定收益。

用户随后明确采纳“原R4＋关闭日志时跳过格式化”为后续实验新基线 `R4-noformat`，冻结源码 source_id=`7d9c295890105a978b6aee4e4109db7967acc8af218474747f21a1873f353c5f`，仅 `bbt/coroutine/detail/Coroutine.cc` 字节变化，未包含A、直接接手、通知或预算策略变更。冻结源码与已验证二进制的关联记录位于 `build-411-yield-diagnosis-r1/adopted-baseline.json`。采纳的是实验比较基线，尚未应用到产品分支或提交；原始采样数值与双worker长尾限制保留。

## 身份与范围

- 原 R4 冻结 source_id：`93a7f6293a23852aa18d509be62d23b556d11d84c3fb7dd1d901c0889cb85062`；不是裸 HEAD，也不是 A。
- Go 及原始驱动身份继承 `tests/reports/work/perf/411-consumer-a-final-r1/manifest.json`，本批实际二进制／库哈希与命令另存本目录 `manifest.json`。
- `direct`：仅将本地某优先级耗尽后的单项 global refill，改为当前 owner 接手执行；保留 admission 双检和 in-flight、READY global 发布、所有通知、预算、BusyScope、CommitYield，以及初始／周期／睡前的原批量路径。已取得任务遇退役时先放回本地，再交原 drain。变化包含队列可见性和续执行顺序，差值不是纯队列函数成本。
- `noformat`：只用 `BBT_COROUTINE_DEBUG_PRINT` 包住 `Coroutine::Resume`、`YieldAndPushGCoQueue` 中的字符串装配；关闭日志时跳过两个 `snprintf`，不修改时钟、预算、队列、通知或上下文切换。
- 两变体相互独立；未测二者组合，不能相加收益。独立源码／diff 在 `build-411-yield-diagnosis-r1/`；原 R4 冻结文件与 A 工作树均未改动。
- 单／双 worker、16 actor；每进程预热 200 ms、正式 1000 ms；固定三轮轮换、24 个时长样本；另 8 个 N=33 有限量正确性预检。只作 `PARTIAL_OBSERVATION`，不套用完整矩阵 BENEFIT／发布资格。

## 证据与失败保留

- 24/24 时长样本、8/8 有限量预检 rc=0、无 timeout，完成／checksum／逐 actor 工作摘要与请求返回／直方图均复核；96/96 raw 流哈希匹配。32 个 sample ID 唯一且与启动前矩阵逐项匹配。
- 时长样本均由 `/proc/PID/maps` 观察到冻结库并核对 payload 身份；有限量进程可能快于 10 ms maps 轮询退出，库路径自报与文件 hash 匹配不等于 maps 已观测。
- 首次预检因上述 maps 观察缺失被拒，正式样本为 0；旧目录 `../411-yield-diagnosis-r1/` 完整保留。修正仅针对有限量预检，正式时长样本仍强制 maps。未为性能方向追加轮次。
- 首次直接接手副本的单测配置因 admission 语句触发测试夹具源码锚点不唯一失败；只加注释区分同语义语句后重验，失败日志保留。最终 direct 聚焦 CTest 6/6，noformat 在相同测试程序、对应库加载路径下 6/6；无新增编译 warning，保留原 CMake CMP0167 开发提示。
- 反汇编确认原 R4／direct 两目标函数各仍调用 `__snprintf_chk`，noformat 两处调用均消失；具体位置记录在 `build-411-yield-diagnosis-r1/format-disassembly-check.json`。
- 未插桩对照的目标进程累计 29.173 秒（含第一次被拒的有限量预检）；合并子代理4次有限检查、父会话2次Go修正后检查及4次观察，累计34.346秒，上限60秒。构建与功能回归另计；未启动完整矩阵或通知／预算实验。
- A 工作树 `bbt/` 的 107 个文件逐一 SHA-256 对照保持一致。

## 线程／actor观察（另行插桩，仅观察原R4与Go）

四个进程各运行一次200ms预热／1000ms观察，单独保存在 `observation/`，不混入前面的三轮未插桩收益。原子账目、完成／checksum和直方图通过；18/18 raw流哈希匹配。子代理的4次有限量检查与6个产物指纹已读回；父会话发现Go原插桩逐操作取局部时间戳地址会逃逸，改为actor私有稳定槽，Go重建及N=33的两项检查通过后才观察，旧检查记录保留。观察版仍有额外工作，不能把其吞吐变化解释为runtime收益。

线程快照的CLK_TCK=100，单tick=10ms；三快照非原子且窗口略宽于正式CPU窗，不能用表中量化值给函数分摊成本。本批共同存活线程匹配，没有观察到新建、退出或不可读线程；不代表在两个端点间出生并退出的线程一定可见。C++统计的是每次业务yield返回后的Processer身份，Go不接入私有P/M接口。每个actor均有进展，但总完成量接近不证明瞬时公平；“最大相邻业务返回间隔”含本actor操作间的辅助工作和宿主抢占，既不是单次yield P99，也不是scheduler无进展的严格上界。

本次R4双worker并未出现一忙一闲或明显分摊失衡；头尾边沿相对1秒窗口也很短，均不支持把本轮倍数级差距直接解释为闲置worker或gate/drain。它们不能排除其他负载／竞争交错，更不能证明队列或通知已是主因。尾窗CPU只作逻辑done后的拆账，不能证明Coroutine／栈／Go GC已物理回收。

## 独立短diff核对与后续取舍

- 独立执行者未参与两个运行时变体，只读核对了短diff。noformat未见额外行为变更或安全阻断项；不是完整产品审查。
- direct存在具体OOM边界：退役时本地归还若enqueue失败，Release下AssertWithInfo只打印后继续，随后清空指针可能丢任务。原R4的单项global转移存在同类模式；本轮没有制造OOM或触发退役失败，不能把正常样本冒充该路径验证。该副本只保留为诊断，不具备产品合入结论。
- 用户已将关闭日志时跳过格式化采纳为后续实验基线；单worker吞吐／CPU／P99改善，双worker吞吐／CPU改善但P99两轮恶化，不声称通用长尾改善。尚未落到产品分支或A上，也没有追加长测。
