# 参数链路与栈池兼容性核查

## Question

## Resolution

### 1. 已核事实及必要变更面
所有源码位置均相对于上述已获取提交，不混用旧 checkout 的 Stop/restart 行为。
- `Scheduler.cc:57-94` 的两个注册入口只接受 callback/description 或 callback/success；调用 `Coroutine::Create` 时读取全局大小与保护开关。`syntax/_CoHelper.hpp:22-29` 的旧宏调用仍经这些入口，保留它们即可保持默认用法。
- `Coroutine.hpp:68-73`、`Coroutine.cc:26-45` 用 `int stack_size`，配置与 `Context` 却用 `size_t`；现有链路存在窄化边界。建议大小全链统一字节类型，入口校验范围；直接旧调用的 ABI 影响须在后续计划/迁移说明明确，不宣称旧二进制无需重编。
- `Context.cc:93-102` 收到大小和保护参数，却仍调用无参 `StackPool::Apply()`，两项参数都没有决定实际分配。应真正传入大小及保护属性。
- `StackPool.cc:83-94,145-151` 只有一个空闲池，新栈读取全局配置；`StackPool.hpp:66-88` 同时有生产队列与 Valgrind 诊断队列类型，改桶时不能漏掉诊断构建。
- `Stack.cc:19-39,154-167` 已用 `memalign + mprotect`，可用大小向上按页对齐，保护页额外分配。无须换 mmap；但现有大小运算未防溢出、分配失败只 assert、设置保护失败的返回值未处理，不能把显式任意大小直接交给这些假设。
- `Context.hpp:68-73` 中用户回调在栈之前初始化，回调复制失败发生在借栈前；`Context.cc:105-115` 则先清两个回调再归还栈。保留这个顺序及 `Test_coroutine_stack.cc:125-150` 析构探针，不在桶改造中回退已修所有权语义。`Coroutine::Create` 在新对象后写 description，发生异常时也必须有唯一清理责任（`Coroutine.cc:28-31`）。

### 2. 最小候选路线（尚待用户一次确认）
- 一个完整路径点覆盖公开 C++ 入口、内部参数传递、按实际大小复用、错误/容量/回收以及测试和适用审查，不把读代码、编码、测试拆成多个路径点。
- 保留原 `RegistCoroutineTask(callback, ...)` 与 `bbtco` 默认行为；增加大小在前的显式 C++ 注册重载，以免与现有 description、bool 输出参数混淆。明确省略与显式零不是同一请求，不用 `0` 作为默认哨兵；`StackPool::Apply()` 可保留为读取全局默认的薄封装，显式路径传大小和保护属性。
- 统一在共享的窄入口完成合法值与大小规范化：正数按页向上取整；零、不可表示/超出安全对象范围、对齐或追加保护页溢出明确失败，不静默回落默认。请求小于一页只按页取整，不擅自设 8/16/32/64 KiB 档或更改 12 KiB 默认；小栈是否足够容纳任务和运行时调用链由真实用例判断，不承诺任意业务在一页栈上安全。
- 缓存键为 `(页对齐后的可用大小, 实际保护属性)`，严格匹配，不借别的较小或更大的档位；归还只根据 Stack 自身不变属性。不改运行中的全局配置以切换大小，不自动扩栈，不改 CoPool。
- 桶与计数同步优先复用既有 `PoolType`，以短临界区维护桶目录和整体不变量；不另做分配器或新依赖。申请/归还/维护必须共享一致的计数协议；分配、释放等系统操作及用户回调不放在桶目录临界区内。若用朴素串行元数据锁，性能天花板和升级条件写 `ponytail:` 注释，并用真实快速回归衡量，不宣称已无锁或性能不变。

### 3. 统一容量、预热与回收
- `GlobalConfig.hpp:60-66` 将池上限绑定最大协程数；当前 `Apply` 是借出数量口径（`AllocSize - idle`），不是字节预算。保留跨桶统一的最大同时借出/预留数，不改成每桶一个上限，也不擅自把它重新定义为内存字节预算。
- `StackPool.cc:85-86,135-137` 的检查与借出分离，且队列 `Size()` 只是参考值（`bbt/core/thread/sync/Queue.hpp:38-49`）。新增或复用之前均要在全池原子/锁协议内预留名额；分配、保护、构造/入队失败须撤销对应预留与所有权，不用近似 Size 判断硬限额，不在失败时虚增总分配数。
- `AllocSize`、`GetCurCoNum`、平均值、最低保留数及 `OnUpdate` 的缩容依据继续是全池口径；最低 128 不能在每桶复制。回收只取空闲栈，不能修改或释放借出栈。空桶元数据寿命与删除须受同一同步协议保护，不留下悬空桶引用。
- 启动预热只针对默认大小/保护属性，不给所有尺寸各建一套。现有 `_Preload` 的 Apply→立即 Release 会重复复用同一块（`StackPool.cc:163-176`）；后续改动须核它与多桶初始化的真实兼容，不用循环次数冒充实际预热块数，不另开通用预热工程。
- `ReleaseUnused` 遍历全部空闲桶并更新全局计数，保持“借出栈已归还且不再提交”的诊断前置条件（`StackPool.hpp:51-52`，`Test_coroutine_stack.cc:153-168`）；它不是 Scheduler 停机入口。
- 显式坏输入、资源分配/保护失败、满容量和缓存归还失败须有明确可观察处理。沿现有异常注册/`succ=false` 路径，析构归还不得抛异常；保护失效的栈不能作为成功栈入池，缓存存放失败要安全释放并正确计数。计划阶段压实错误类别与受控验证手段，不因 assert 编译差异改变 Release 结果。

### 4. 直接兼容性与真实验证出口
